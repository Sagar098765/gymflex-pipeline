GYMFLEX DEVOPS STARTER FILES

EXPECTED REPOSITORY STRUCTURE (repository root: D:\Gymflex website)

Gymflex website/                    <- Git repository root
  Gymflex website/                  <- existing website assets folder
    Frontend/
      index.html
      style.css
      javascript.js
    Images/
      (your image files)
  gymflexapp/
    pom.xml                          <- replace with this bundle's gymflexapp/pom.xml
    src/
      main/java/                     <- old Java backend source is retained but skipped by this static-site POM
      main/resources/
      test/java/                     <- old Java tests are not compiled/run by this static-site POM
      test/resources/
    target/                          <- generated by Maven; do not commit
      gymflex.war
  Dockerfile                         <- place at repository root
  Jenkinsfile                        <- place at repository root
  .gitignore                         <- place at repository root

IMPORTANT SCOPE
This setup builds the static HTML/CSS/JavaScript website into a WAR and serves it from Tomcat.
It intentionally skips existing Java source/test compilation because the previous build log showed
missing Spring Boot, Jersey, Jackson, MessagePack and javax.* dependencies. Those Java classes are
therefore NOT part of the deployed GymFlex application in this setup. They are not deleted; configure
them as a separate backend project later if you want to run that API.

The Jenkins Test stage validates that the WAR contains index.html, style.css, javascript.js, and at
least one image under Images/. It is not a browser test and does not test Java methods.

LOCAL BUILD (PowerShell)
1. cd "D:\Gymflex website"
2. mvn -f .\gymflexapp\pom.xml clean package
3. Test-Path .\gymflexapp\target\gymflex.war
4. jar tf .\gymflexapp\target\gymflex.war

DOCKER (run from repository root)
1. docker build -t gymflex:1.0 .
2. docker rm -f gymflex-container 2>$null
3. docker run -d --name gymflex-container -p 8081:8080 gymflex:1.0
4. Open http://localhost:8081/
5. docker logs gymflex-container

JENKINS
- Put Jenkinsfile in repository root.
- Create a Pipeline job. Use Pipeline script from SCM if desired, with Git repository URL:
  https://github.com/Sagar098765/gymflex-pipeline.git
- Branch: main; Script Path: Jenkinsfile.
- The Jenkins agent must be Windows and must have Git, Java and Maven available to the Jenkins service account.

ARTIFACTS
The Maven project generates gymflexapp/target/gymflex.war. It does not generate a JAR.
The Jenkins archive pattern includes both JAR and WAR patterns, but only files that actually exist
are archived. A JAR should not be fabricated just to make both extensions appear.
